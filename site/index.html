What it does

One agent on every channel, in the patient's language (the demo shows English over RCS and Spanish over WhatsApp).

01 · EXPLAIN

What do I owe, and why?

The adjudicated claim, line by line: what was billed, what insurance discounted (never owed), and the patient's share with the reason: deductible, copay or coinsurance.

02 · ARRANGE

A plan the patient chose

Only the options the practice's policy engine issues. The patient enrols with their own "yes", pays through a secure link, and gets the confirmation by Amazon SES.

03 · ESCALATE

Humans for the hard parts

"I already paid" is investigated read-only. The agent finds the unapplied front-desk payment and opens a staff ticket with the evidence and the exact fix.

Policy lives in code, not in the prompt

The model decides what to say and which tool to call. The tools decide what's allowed, and every rule is a unit test that runs in CI.

Architecture

Messages come in on each channel and go to one agent in AgentCore, and replies go out on the same channel. It's one AWS CDK stack.

Try it

You can run the same tools and guardrails locally, without an AWS account:

git clone https://github.com/icohangar-ops/settle-agent && cd settle-agent
uv venv -p 3.12 .venv && uv pip install -p .venv -e ".[dev]"
.venv/bin/pytest -q                 # guardrail tests
.venv/bin/python -m sim.run_demo    # both demo conversations
To deploy it to your own AWS account and chat with it from your phone, follow docs/DEPLOY.md. The steps are: CDK deploy, create an RCS test agent, register your phone as a tester, and run scripts/start_demo.py.
